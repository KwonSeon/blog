# 외부 알림 운영

P2-005 구현 / P2-006 조사 결정. 기본 채널은 회원 알림함이며, Telegram은 선택적으로 연결한다. 개발·운영 배포 기본값은 비활성이다. 실제 봇·수신 동의·실발송 왕복은 아직 검증하지 않았다.

## Telegram 연결

1. 전용 봇과 수신자 동의를 준비한다. 수신자가 봇과 대화를 시작하고 관리자가 실제 개인 대화 ID와 공통 Identity subject의 소유 관계를 확인한다. 공유 그룹에 개인 알림을 연결하지 않는다.
2. Git 밖 API 런타임에 아래 설정을 저장한다. 계정마다 동의/해지 요청을 별도 운영 기록에 남긴다. 봇 토큰이나 대화 ID를 문서·로그·브라우저에 노출하지 않는다.
   - `BLOG_TELEGRAM_ENABLED=true`
   - `BLOG_TELEGRAM_TOKEN`: BotFather에서 발급한 토큰
   - `BLOG_TELEGRAM_RECIPIENTS`: `identitySubject:privateChatId`를 쉼표로 구분한 명시적 매핑
   - `BLOG_TELEGRAM_SITE_URL`: 해당 환경 HTTPS 루트 주소
3. 배포 후 `/admin/notifications`에서 준비 상태를 확인한다. 수신 동의와 매핑을 검토했다는 체크를 선택하고 발송을 시작한다. 관리자 권한은 기존 명시적 Identity→author 바인딩으로 판정한다.
4. 별도로 승인된 테스트 수신자에게 댓글/답글 이벤트 하나로 실발송을 검증한다. 이번 개발 검증은 모의 전송만 사용하며 실제 메시지를 보내지 않는다.

환경 설정만으로 전송되지 않는다. DB가 활성화한 설정 지문과 일치하는 워커만 전송한다. 토큰·수신자·주소를 변경하면 새로운 설정을 다시 확인해야 한다. 블루그린 이전 워커는 새 지문에 해당하는 큐를 처리할 수 없다. 동의 철회 시 먼저 발송을 중지한 뒤 매핑을 제거·배포한다. 이미 전송 중인 요청이 끝날 때까지 중지 요청이 기다릴 수 있다. 환경 변수만 끄면 이전 배포 워커에는 적용되지 않으므로 먼저 DB 중지를 사용한다.

## 전달 및 실패 의미

- 댓글·회원 알림·전송 대기열은 같은 트랜잭션에 기록된다. 활성화 전 알림은 소급 발송하지 않는다.
- 같은 알림/설정은 한 번만 큐에 넣는다. 계정 subject와 텍스트는 외부 요청에 넣지 않고, 일반 새 알림 문구와 로그인 필요한 알림함 링크만 보낸다.
- 공개/발행 상태, 댓글 삭제, 90일 보관 기한을 발송 직전에 검사한다. 내용 변경과 동시에 진행 중인 일반 알림 안내까지 철회할 수는 없다.
- DB 전역 잠금과 발송 간격으로 여러 워커를 직렬화한다. 최대 분당 약15건이며, 더 엄격한 Telegram 제한이 응답하면 대기한다. 유료 broadcast는 항상 false다.
- `SENDING`을 먼저 커밋한다. 네트워크 단절·응답 해석 실패·5xx·중단된 워커는 `UNKNOWN`으로 끝나며 자동 재전송하지 않는다. Telegram의 요청 중복 제거를 보장하지 않으므로 정확히 한 번 전달을 주장하지 않는다.
- 명시적429만 최대6회 시도, `retry_after` 5~3600초로 제한한다. 그 외4xx는 실패로 끝난다.
- 5분 넘은 `SENDING`은 구성된 워커가 `UNKNOWN`으로 복구한다. 기능 자체가 꺼졌으면 스케줄러는 DB에도 접근하지 않는다.
- 이전 지문 대기열은 새 수신자에게 재지정되지 않는다. 같은 설정으로 다시 활성화하면 남은 대기열을 이어서 처리한다. 90일 알림 정리 또는 원본 삭제 시 FK cascade로 전송 기록도 제거된다.
- `UNKNOWN`을 SQL로 `QUEUED`로 되돌리지 않는다. 실제 전달 여부를 먼저 확인한다. 전송 성공은 Telegram API가 수락했다는 의미이며 사람이 읽었다는 뜻이 아니다.

## 카카오 결정

현재는 카카오 알림톡 연동을 활성화하지 않는다. 카카오 로그인 연결은 서비스 알림톡 전송 권한을 제공하지 않는다. 사용자 간 카카오톡 메시지 API는 앱 연결/메시지 동의/친구 관계 등 별도 조건이 있어 일반 블로그 알림 채널로 대체하지 않는다.

추후 비즈니스 채널 승인, 발송 서비스 계약과 자격, 템플릿 승인, 목적별 수신 근거와 해지 처리, 요금/한도 및 테스트 계정이 준비되면 별도 공급자 어댑터를 추가한다. 전화번호를 지금 수집하거나 유료 계약을 자동 생성하지 않는다. 그동안 회원 알림함과 선택적 Telegram을 사용한다.
